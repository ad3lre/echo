# Internationalization (i18n)

Echo uses [vue-i18n](https://vue-i18n.intlify.dev/) for UI string translation. Locale catalogs live under `clients/web/src/i18n/locales/`.

## Conventions

- **Key naming:** `feature.section.element` — e.g. `settings.sections.profile.blurb`, `errors.api.NOT_SERVER_MEMBER`.
- **New strings:** use `$t('key')` in Vue templates or `echoT('key')` / `useI18n().t('key')` in script. Do not add new hardcoded English in user-facing UI.
- **Interpolation:** `{name}` placeholders — `echoT('time.todayAt', { time: '3:00 PM' })`.
- **Plurals:** vue-i18n pipe syntax — `no members | one member | {count} members`.
- **Accessibility:** translate `aria-label`, `title`, and `placeholder` via `:aria-label="$t('…')"`.

## Locales

| Locale  | Catalog                                              | Notes                        |
| ------- | ---------------------------------------------------- | ---------------------------- |
| `en-US` | Source of truth (merged JSON under `locales/en-US/`) | Default                      |
| `en-GB` | `locales/en-GB.json`                                 | Partial; falls back to en-US |
| `pt-BR` | `locales/pt-BR/` (full mirror of en-US namespaces)   | Full key parity with en-US   |
| `de`    | `locales/de/` (full mirror of en-US namespaces)      | Full key parity; lazy-loaded |

Namespaces include product chrome (`layout`, `chat`, `auth`, settings shells), plus feature catalogs such as `channelPanel`, `memberProfile`, `safety`, `paperUi`, `settingsUi`, `serverSettingsUi`, and `voiceChrome` (non-game voice UI). Voice/game activities stay English.

Auth profile locales (`contracts/echoLocale.ts`) also allow `es` (Apple String Catalog) alongside the web UI locales above. The Apple String Catalog covers `en`, `es`, `pt-BR` and `de`.

Legal markdown for `de` is not translated yet and falls back to en-US with the in-app fallback notice (legal text needs a human/legal translation).

User locale is stored in `localStorage` and on the auth profile (`locale` column). Boot order: profile → localStorage → `navigator.language` → `en-US`.

## API errors

Backend returns English `message` for logs/support. The client maps stable `code` / `detail` tokens via `clients/web/src/i18n/apiErrors.ts` (`translateApiErrorBody`).

## Legal & marketing

- Legal markdown: `marketing/terms/{locale}/*.md` with en-US fallback.
- Marketing: `marketing/src/i18n/{locale}.json` and Astro i18n routing.

## Scripts

```bash
bun run --filter web i18n:check   # en-GB subset of en-US; pt-BR and de full key parity vs en-US
```

## Adding a locale

1. Copy `locales/en-US/` structure or add `locales/{locale}.json`.
2. Register in `SUPPORTED_ECHO_UI_LOCALES` in `clients/web/src/i18n/index.ts`.
3. Add `languageOptions` entry in `timeLanguagePreferences.ts`.
4. Extend `contracts/echoLocale.ts` if the locale is stored on the auth profile.
5. Run `bun run --filter web i18n:check`.
