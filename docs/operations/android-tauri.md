# Echo Android (Tauri)

**Release quick ref:** [`releases/android.md`](../../releases/android.md) — AAB/APK output paths and CI artifact name.

Native shell around the same Vue SPA as the web and desktop apps. **Package id:** `com.echo.app` ([`src-tauri/tauri.android.conf.json`](../../src-tauri/tauri.android.conf.json)) — distinct from desktop `com.echo.desktop`.

**Desktop operations:** [desktop-windows.md](desktop-windows.md) · [tauri-phase2.md](tauri-phase2.md)

## Prerequisites (developers)

- **Node** 22+ (repo root).
- **JDK 17** — Eclipse Temurin recommended; set `JAVA_HOME`.
- **Android Studio** or standalone **Android SDK + NDK** — set `ANDROID_HOME` (and usually `NDK_HOME` / `ANDROID_NDK_HOME` per your Rust/Android toolchain).
- **Rust** stable ≥ [`src-tauri/Cargo.toml`](../../src-tauri/Cargo.toml) `rust-version`; add targets:

  ```bash
  rustup target add aarch64-linux-android x86_64-linux-android
  ```

- Run `npm ci` from the repo root.

## First-time: generate `src-tauri/gen/android`

The Gradle project under `src-tauri/gen/android` is generated by the Tauri CLI (do not hand-edit without knowing what will be overwritten on `android init`).

```bash
npm run tauri:android:init
```

If this fails, ensure `java` is on `PATH` / `JAVA_HOME` is set and the Android SDK is installed.

## Environment variables (build)

| Variable             | Purpose                                                                              |
| -------------------- | ------------------------------------------------------------------------------------ |
| `VITE_ECHO_TAURI`    | Set to `1` for any Tauri shell (set automatically by npm scripts).                   |
| `VITE_ECHO_ANDROID`  | Set to `1` for Android builds (set by `tauri.android.conf.json` and npm scripts).    |
| `VITE_API_URL`       | **Required** for release builds — HTTPS API origin (same contract as desktop).       |
| `VITE_SOCKET_IO_URL` | **Required** for release builds — Socket.IO origin (same host as API in production). |

Frontend logic uses [`IS_ECHO_TAURI_SHELL`](../../frontend/src/config.ts) for API/socket resolution and OAuth encoding; desktop-only UI still checks `VITE_ECHO_DESKTOP`.

## npm scripts (repo root)

| Script                                  | Description                                                                                                      |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `npm run tauri:android:init`            | `tauri android init --ci` — creates/refreshes `gen/android`.                                                     |
| `npm run tauri:android:dev`             | Dev server + deploy to device/emulator (`tauri android dev`).                                                    |
| `npm run tauri:android:build`           | Production Android build via [`scripts/tauri-android-build.mjs`](../../scripts/tauri-android-build.mjs).         |
| `npm run tauri:android:build:chat-echo` | Same with **`VITE_API_URL`** and **`VITE_SOCKET_IO_URL`** set to `https://chat-echo.com` (production Echo host). |

Pass extra CLI args after `--`, e.g. `npm run tauri:android:build -- -- --apk` for an APK (see current `tauri android build --help`).

## Signing (Play / release)

Follow [Tauri — Android code signing](https://v2.tauri.app/distribute/sign/android/):

1. Create an upload keystore with `keytool`; enable **Google Play App Signing**.
2. At build time, write `src-tauri/gen/android/keystore.properties` (not committed — see root `.gitignore`). Use `keyAlias`, `storeFile`, and either the single `password` field from the Tauri docs or separate `storePassword` / `keyPassword` (see [`keystore.properties.example`](../../src-tauri/gen/android/keystore.properties.example)).
3. [`app/build.gradle.kts`](../../src-tauri/gen/android/app/build.gradle.kts) loads that file for **release** signing when it exists. If the file is absent, **release is signed with the debug keystore** so sideloaded release APKs/AABs from local builds install on devices—re-apply equivalent Gradle wiring after regenerating `gen/android` if init overwrites it.

**Sideload troubleshooting:** An unsigned release APK often fails with a generic **App not installed** on device (Package Installer gives almost no detail). Ensure the artifact is signed (upload keystore or the debug fallback above). If you previously installed another build signed with a different key, uninstall first. Prefer a **universal** APK/AAB or match the device ABI (for example `*-arm64-*` for typical phones, `*-x86_64-*` for many emulators). On Windows, `tauri android build` may require **Developer Mode** (symlinks into `jniLibs`)—see the CLI error text if the build stops after Rust compile.

CI can materialize `keystore.properties` from GitHub Actions secrets (`ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`, `ANDROID_KEY_BASE64`) using the same pattern as the Tauri documentation.

## OAuth / deep links (Android)

Desktop uses custom scheme `echo://` ([`src-tauri/tauri.conf.json`](../../src-tauri/tauri.conf.json) plugin config). The same repo wires **Android** via `plugins.deep-link.mobile`: a dedicated intent filter for the `echo` scheme is emitted at build time by [`tauri-plugin-deep-link`](https://github.com/tauri-apps/plugins-workspace/tree/v2/plugins/deep-link) into `AndroidManifest.xml` (replacing the `DEEP LINK PLUGIN` placeholders). Register matching redirect URIs in Discord/Google consoles and Echo backend allowlists.

**Optional HTTPS App Links** (e.g. `https://chat-echo.com/...`) require hosting `.well-known/assetlinks.json`, signing fingerprints, and an extra `mobile` entry such as `{ "scheme": ["https"], "host": "chat-echo.com", "pathPrefix": ["/your-path"], "appLink": true }` — only add after backend routes and Digital Asset Links are verified.

## OS integration (launcher, shell, backup)

These live under **`src-tauri/gen/android/`** (generated by `tauri android init`, but tracked in-repo here). After **`npm run tauri:android:init`**, diff `gen/android` and reapply any manual tweaks:

| Area                 | What was customized                                                                                                                                                                                       |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Deep link            | `plugins.deep-link` in [`src-tauri/tauri.conf.json`](../../src-tauri/tauri.conf.json) (not in `gen/`)                                                                                                     |
| Launcher             | `res/mipmap-anydpi-v26/ic_launcher.xml`, `ic_launcher_round.xml`, monochrome drawable + colors; templates also under [`src-tauri/icons/android/`](../../src-tauri/icons/android/) for `tauri icon` / init |
| Splash (Android 12+) | `Theme.Echo.Splash`, `androidx.core:core-splashscreen`, [`MainActivity.kt`](../../src-tauri/gen/android/app/src/main/java/com/echo/app/MainActivity.kt) `installSplashScreen()`                           |
| Edge-to-edge         | `Theme.Echo` transparent system bars + Contrast enforcement off; `enableEdgeToEdge()` in `MainActivity`                                                                                                   |
| Backup               | `res/xml/backup_rules.xml`, `data_extraction_rules.xml` — excludes app **cache** / **code_cache** from cloud backup and device transfer                                                                   |
| Notifications        | `POST_NOTIFICATIONS` in the manifest (runtime prompt on API 33+ when used)                                                                                                                                |
| Locale / config      | Extra `android:configChanges` entries on `MainActivity` for `layoutDirection`, `density`, `fontScale`, `colorMode`, etc.                                                                                  |

No foreground service was added (not required for the current WebView + notification usage).

## After upgrading `@tauri-apps/cli`

Re-run `npm run tauri:android:init`, diff `gen/android`, and reapply any manual Gradle signing or packaging tweaks.
