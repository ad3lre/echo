# Session Diagnostics

This project records dev-localhost diagnostics into per-session artifacts under:

- `.diagnostics/sessions/session_<timestamp>_<id>/`

## Files

- `manifest.json`: session metadata (`sessionId`, start/end time, process info)
- `frontend_events_###.jsonl`: frontend event batches
- `backend_events_###.jsonl`: backend lifecycle/domain events
- `spans_###.jsonl`: canonical merged stream for chain reconstruction
- `errors.jsonl`: generated by summarize script
- `chains.jsonl`: generated by summarize script

## Workflow

1. Reproduce the issue in local dev.
2. Resolve the most recent session path:
   - `npm run diagnostics:latest`
3. Build summarized artifacts:
   - `npm run diagnostics:summarize`
4. For AI-driven debugging, inspect in this order:
   - `errors.jsonl`
   - `chains.jsonl`
   - raw `spans_###.jsonl`, then frontend/backend split files

## Correlation

- Frontend emits `traceId`/`spanId`.
- HTTP requests carry:
  - `X-Diag-Trace-Id`
  - `X-Diag-Span-Id`
  - `X-Diag-Parent-Span-Id` (optional)
- Backend emits child spans under incoming trace context.

## Safety + Scope

- Backend session diagnostics are enabled only when `ECHO_SESSION_DIAGNOSTICS=true`.
- Enabled for `import.meta.env.DEV` + localhost frontend host.
- Ingest endpoint is localhost-only.
- Context fields are sanitized with allowlist-first filtering and sensitive-key stripping.

### Enable / disable

- Disabled by default (`ECHO_SESSION_DIAGNOSTICS=false`).
- Enable locally when debugging:
  - PowerShell: `$env:ECHO_SESSION_DIAGNOSTICS='true'`
  - Then start the backend in the same shell session.

## V1 optimization (AI-readability)

To reduce token footprint and parsing time for AI-driven debugging, diagnostics apply a safe V1 optimization:

- `warn` / `error` / `fail` events are **never sampled**.
- events that include an `error` payload are **never sampled**.
- repetitive `info` success/end events are sampled and short-window coalesced.

Defaults:

- sample rate: `0.25`
- coalesce window: `1500ms`

### Overrides

Backend (Node env):

- `DIAG_SAMPLE_SUCCESS_RATE` (0..1)
- `DIAG_COALESCE_WINDOW_MS` (integer ms)
- `DIAG_OPTIMIZE_VERBOSE=true` (emit close-time optimization info)

Frontend (Vite env):

- `VITE_DIAG_SAMPLE_SUCCESS_RATE` (0..1)
- `VITE_DIAG_COALESCE_WINDOW_MS` (integer ms)

Set sample rate to `1` and coalesce window to `0` for deep local repros when you want full success-event fidelity.
